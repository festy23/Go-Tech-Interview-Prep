# Работа с сервером в Go

Go стал стандартом для написания HTTP-серверов и микросервисов не случайно: стандартная библиотека предоставляет всё необходимое из коробки, а производительность превосходит большинство JVM-платформ при в разы меньшем потреблении памяти. Для собеседований серверная разработка — одна из самых частых тем: от вопросов о жизненном цикле запроса до задач на graceful shutdown, аутентификацию и тестирование.

## Зачем Go для серверов

Каждый входящий HTTP-запрос Go обрабатывает в отдельной горутине — без пула потоков, без колбэков, без `async/await`. Код выглядит последовательным, но на самом деле конкурентен. При нагрузке в 10 000 одновременных запросов сервер на Go потребляет порядка 80–100 МБ оперативной памяти там, где Node.js потребует 400–600 МБ, а Java Spring — от 1 ГБ.

Ключевые преимущества для серверной разработки:
- **Пакет `net/http`** — полноценный HTTP/1.1 и HTTP/2 сервер в стандартной библиотеке.
- **`ServeMux` с Go 1.22** — расширенные паттерны маршрутизации (`GET /api/{id}`) без сторонних библиотек.
- **`context.Context`** — сквозное распространение отмены, дедлайнов и трейсинга.
- **Горутины** — дешёвая конкурентность без явного управления потоками.

## Устройство HTTP-сервера

Минимальный HTTP-сервер на Go:

```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("GET /hello", func(w http.ResponseWriter, r *http.Request) {
        fmt.Fprintln(w, "Hello, Go 1.25!")
    })

    http.ListenAndServe(":8080", nil)
}
```

За этим кодом стоит несколько слоёв абстракции: `ListenAndServe` создаёт TCP-сокет, принимает соединения в цикле и запускает для каждого запроса горутину, которая вызывает нужный обработчик через `ServeMux`.

С Go 1.22 `ServeMux` поддерживает метод HTTP в паттерне (`GET /api/{id}`), а `r.PathValue("id")` извлекает переменную из пути — без сторонних роутеров для большинства задач.

## Обработчики и middleware

Центральная абстракция сервера — интерфейс `http.Handler`:

```go
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}
```

Любая структура, реализующая `ServeHTTP`, является обработчиком. Для функций удобна обёртка `http.HandlerFunc`. Middleware строится по принципу цепочки: каждый слой оборачивает следующий и добавляет логику до и/или после него.

```go
func LoggingMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        start := time.Now()
        next.ServeHTTP(w, r)
        slog.Info("request", "method", r.Method, "path", r.URL.Path,
            "duration", time.Since(start))
    })
}
```

Типичный стек middleware: логирование → трейсинг → аутентификация → авторизация → обработчик бизнес-логики. Подробнее о маршрутизации, `r.PathValue()` и сравнении со сторонними роутерами — в статье **«Обработчики»**.

## Аутентификация и безопасность

Серверные приложения практически всегда требуют аутентификации. Go не навязывает конкретный подход, и это плюс: вы контролируете каждую деталь.

**JWT** — самый распространённый формат токенов для stateless-аутентификации. Сервер подписывает токен при входе пользователя и проверяет подпись при каждом запросе. Никакого хранилища сессий не нужно.

**Сессии** — традиционный подход: сервер хранит сессии в Redis или PostgreSQL, клиенту выдаётся только идентификатор в cookie. Проще инвалидировать, но требует хранилища.

**OAuth 2.0** — делегирование аутентификации провайдеру (Google, GitHub, Yandex). Пакет `golang.org/x/oauth2` предоставляет готовый client.

**Пароли** — хранятся только в виде bcrypt-хешей (`golang.org/x/crypto/bcrypt`). Никогда не MD5/SHA без соли.

Аутентификация реализуется как middleware: проверяет заголовок `Authorization`, валидирует токен, кладёт данные пользователя в контекст. Подробнее — в статье **«Аутентификация»**.

## Обработка ошибок

Идиоматичная обработка ошибок — одно из главных отличий Go от других языков. Нет исключений, нет скрытого `try/catch`. Каждая ошибка возвращается явно и обрабатывается в месте возникновения.

В серверном коде это выражается в трёх паттернах:

1. **Обёртка ошибок** через `fmt.Errorf("операция: %w", err)` сохраняет цепочку для `errors.Is`/`errors.AsType`.
2. **Централизованный обработчик ошибок** — единая функция превращает Go-ошибку в HTTP-ответ с правильным статусом и JSON-телом.
3. **Middleware паники** — `recover()` в defer перехватывает неожиданную панику и возвращает 500 вместо падения сервера.

```go
func writeError(w http.ResponseWriter, err error) {
    if httpErr := errors.AsType[*HTTPError](err); httpErr != nil {
        respond(w, httpErr.Status, httpErr)
        return
    }
    respond(w, http.StatusInternalServerError,
        map[string]string{"error": "internal server error"})
}
```

Подробнее об иерархии ошибок, кодах и валидации — в статье **«Обработка ошибок»**.

## Тестирование серверов

Go предоставляет пакет `httptest`, который позволяет тестировать HTTP-обработчики без реального сетевого соединения. `httptest.NewRecorder()` захватывает ответ, `httptest.NewServer()` поднимает реальный локальный сервер для интеграционных тестов.

С Go 1.24 `t.Context()` автоматически создаёт контекст, отменяемый в конце теста — больше не нужно вручную вызывать `cancel()` в каждом тест-кейсе. `b.Loop()` в бенчмарках (Go 1.24) заменяет старый `for range b.N` и корректно учитывает операции setup.

```go
func TestHelloHandler(t *testing.T) {
    req := httptest.NewRequest(http.MethodGet, "/hello", nil).
        WithContext(t.Context())
    w := httptest.NewRecorder()

    HelloHandler(w, req)

    if w.Code != http.StatusOK {
        t.Errorf("got %d, want 200", w.Code)
    }
}
```

## Типичные вопросы на собеседованиях

**Как работает graceful shutdown?** Сервер принимает сигнал ОС (`SIGTERM`, `SIGINT`), перестаёт принимать новые соединения и ждёт завершения текущих запросов через `server.Shutdown(ctx)`. Без этого Docker/Kubernetes могут обрезать запросы на лету.

```go
srv := &http.Server{Addr: ":8080", Handler: mux}

go func() {
    sigCh := make(chan os.Signal, 1)
    signal.Notify(sigCh, syscall.SIGTERM, syscall.SIGINT)
    <-sigCh

    ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
    defer cancel()
    srv.Shutdown(ctx)
}()

srv.ListenAndServe()
```

**Зачем `ReadTimeout` и `WriteTimeout`?** Без таймаутов медленный клиент («slowloris») может заблокировать горутину навсегда. Рекомендуемые значения: `ReadTimeout: 5s`, `WriteTimeout: 10s`, `IdleTimeout: 120s`.

**Как передать зависимости в обработчик?** Через замыкание или структуру. Глобальные переменные не используются — они нарушают тестируемость.

```go
type Server struct {
    db  *sql.DB
    log *slog.Logger
}

func (s *Server) handleUsers(w http.ResponseWriter, r *http.Request) {
    // s.db и s.log доступны без глобального состояния
}
```
