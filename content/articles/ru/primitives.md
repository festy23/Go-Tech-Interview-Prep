# Примитивы Go

Go — язык со статической типизацией и небольшим ядром. Большинство программ строится на нескольких фундаментальных типах: строках, срезах, отображениях и интерфейсах. Понимание того, как эти типы устроены внутри, отличает разработчика, который просто пишет код, от того, кто пишет эффективный и предсказуемый код.

## Почему примитивы важны на собеседованиях

На Go-интервью редко спрашивают академические вопросы о теории типов. Зато очень часто задают практические задачи, в которых нужно знать:

- Что происходит при `append`, когда исчерпана ёмкость среза
- Почему итерация по map не детерминирована
- Чем опасен сабсрез с точки зрения утечки памяти
- Что такое nil-интерфейс и почему `nil != nil` — валидное утверждение в Go
- Как работает UTF-8 и почему `len(s)` != количество символов в строке

Это не академические вопросы — это реальные ловушки, которые встречаются в продакшне.

## Система типов Go

### Базовые типы

Go делит типы на несколько категорий:

**Числовые**: `int`, `int8`, `int16`, `int32`, `int64`, `uint`, `uint8` (`byte`), `uint16`, `uint32`, `uint64`, `float32`, `float64`, `complex64`, `complex128`, `uintptr`

**Строковый**: `string` — неизменяемая последовательность байт в кодировке UTF-8

**Булев**: `bool`

**Составные**: массивы, срезы, отображения, структуры, указатели, функции, каналы, интерфейсы

### Числовые типы

`int` и `uint` зависят от платформы: на 64-битных системах это 64 бита. Для явного контроля размера используйте `int64`, `int32` и т.д.

```go
var x int = 42
var y int64 = 42

// int и int64 — разные типы, требуется явное преобразование
z := int64(x) + y
```

Начиная с Go 1.21, встроенные функции `min` и `max` работают с любыми упорядоченными типами:

```go
a, b := 3, 7
fmt.Println(min(a, b)) // 3
fmt.Println(max(a, b)) // 7

// Работает со срезами тоже
nums := []int{5, 2, 8, 1}
fmt.Println(min(nums...)) // 1
```

### Константы и iota

Константы в Go вычисляются на этапе компиляции и могут быть нетипизированными:

```go
const Pi = 3.14159 // нетипизированная константа

type Weekday int

const (
    Sunday Weekday = iota // 0
    Monday                // 1
    Tuesday               // 2
)
```

## Строки

Строка в Go — это неизменяемый срез байт. Операции вроде конкатенации создают новую строку. Итерация по строке через `range` возвращает руны (Unicode code points), а не байты.

```go
s := "Привет"
fmt.Println(len(s))        // 12 — байты, не символы!
fmt.Println(len([]rune(s))) // 6 — символы

for i, r := range s {
    fmt.Printf("%d: %c (%d)\n", i, r, r)
}
```

Пакет `strings` содержит богатый набор утилит. С Go 1.18 появился `strings.Cut`, с Go 1.20 — `strings.CutPrefix`, `strings.CutSuffix` и `strings.Clone`. Для эффективного построения строк используется `strings.Builder`.

Подробнее — в статье **Strings**.

## Срезы

Срез — это заголовок из трёх полей: указатель на массив, длина (`len`) и ёмкость (`cap`). Это ключевая структура данных Go, используемая буквально везде.

```go
s := make([]int, 3, 5) // len=3, cap=5
s = append(s, 10)      // len=4, cap=5
s = append(s, 20)      // len=5, cap=5
s = append(s, 30)      // len=6, cap=10 — перевыделение!
```

Пакет `slices` (Go 1.21) предоставляет типобезопасные утилиты: `slices.Sort`, `slices.Contains`, `slices.Compact`, `slices.Clone`, `slices.Clip`.

Подробнее — в статье **Slices**.

## Отображения (Maps)

Map в Go — хэш-таблица. Порядок итерации намеренно рандомизирован. Конкурентный доступ без синхронизации вызывает панику в рантайме.

```go
m := map[string]int{"a": 1, "b": 2}

// Безопасное чтение с проверкой существования
v, ok := m["c"]

// clear — встроенная функция (Go 1.21)
clear(m) // удаляет все элементы

// maps.Keys (Go 1.23)
keys := maps.Keys(m)
```

Подробнее — в статье **Maps**.

## Интерфейсы

Интерфейс в Go реализуется неявно — достаточно реализовать методы. Внутри интерфейс — это пара указателей: на таблицу методов (itab) и на данные.

```go
type Stringer interface {
    String() string
}

type Point struct{ X, Y int }

func (p Point) String() string {
    return fmt.Sprintf("(%d, %d)", p.X, p.Y)
}

var s Stringer = Point{1, 2}
fmt.Println(s.String()) // (1, 2)
```

Наиболее распространённая ловушка — nil-интерфейс vs интерфейс, хранящий nil-указатель. Это разные вещи, и путаница приводит к трудновоспроизводимым багам.

Подробнее — в статье **Interfaces**.

## Современный Go (1.21–1.25)

В последних версиях Go добавлено много полезного:

| Версия | Новинка |
|--------|---------|
| 1.21 | `min`, `max`, `clear` — встроенные; пакеты `slices`, `maps`, `cmp` |
| 1.21 | `slices.Sort`, `slices.Contains`, `slices.Compact` |
| 1.22 | `for i := range n` — range по целому числу |
| 1.23 | `maps.Keys`, `maps.Values` возвращают итераторы |
| 1.24 | Улучшения runtime, Swiss Tables для map |
| 1.25 | Дальнейшие улучшения производительности, `cmp.Or` |

Цикл `for i := range n` заменяет verbose `for i := 0; i < n; i++`:

```go
for i := range 5 {
    fmt.Println(i) // 0, 1, 2, 3, 4
}
```

`cmp.Or` возвращает первое ненулевое значение:

```go
name := cmp.Or(os.Getenv("NAME"), "anonymous")
```

## Что спрашивают на интервью

**Самые частые темы:**

1. Разница между `nil` срезом и пустым срезом (`[]int{}`)
2. Что происходит при записи в nil-map
3. Почему нельзя конкурентно читать/писать в map
4. Чем `string([]byte{...})` дороже, чем кажется
5. Как работает `append` при нехватке ёмкости
6. Что такое nil-интерфейс и чем он отличается от интерфейса с nil-значением
7. Как `range` обходит строку (по байтам или рунам?)
8. Что означает утечка памяти через сабсрез

**Типичная задача:**

```go
func reverseWords(s string) string {
    words := strings.Fields(s)
    slices.Reverse(words) // Go 1.21
    return strings.Join(words, " ")
}
```

## Итог

Примитивы Go — это не просто синтаксис. Каждый из них имеет чёткую семантику и внутреннее устройство, которое напрямую влияет на производительность и корректность кода. Строки — неизменяемы и UTF-8. Срезы — трёхполевой заголовок поверх массива. Maps — хэш-таблицы с намеренно рандомизированным порядком. Интерфейсы — пара указателей с неявной реализацией.

Изучите детальные статьи по каждому типу, чтобы быть готовым к любому вопросу на собеседовании.
